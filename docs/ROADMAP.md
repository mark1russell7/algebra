# Roadmap

This file is the plan of algebra. The Status page of the site reads it, and the tracker of the project mirrors it.

Each item writes its prediction before its code: the claims, how each claim is measured, its base and its noise.

| ID | Item | Status | Summary |
| --- | --- | --- | --- |
| A1 | Expression documents | done 2026-11-02 (#8) | The package `@mark1russell7/expression`. The coeval kinds of an expression: numbers, variables, the field operations, powers, roots, `min`, `max` and comparisons. Each node keeps a summary monoid: free variables, degree, bounds and cost. A zod schema and a generator of random expressions for property tests. |
| A2 | Exact rationals | done 2026-11-03 | Rationals over `bigint`, always in lowest terms. The start is the rationals of `@mark1russell7/quantity` in systems: they move here, and quantity imports them (systems #284). Property tests of the field laws. The time claim holds: each of 32 cases of the tests of quantity is within 2× of the old rationals (bench run 41647641389). The root `root(a, k)` and `integerRoot(n, k)` (0.1.1) give the exact verb a claim for each rational root. |
| A3 | The float evaluator | done 2026-11-02 (#30) | An expression compiles once to a JavaScript function of its variables, with no `eval` at run time. It also gives a bound of its rounding error from the summary of each node. The verb `float` of the expression kinds is the evaluator, and `compileFloat` gives the function. Time claim: within 1.5× of a hand-written function on the corpus of A12. `packages/expression-bench` and `bench-expression.yml` time it against a written function of each document (#49). Left: the CI run of the bench. |
| A4 | Interval and ball arithmetic | done 2026-11-02 (#35) | Intervals with outward rounding (one step of `nextafter` on each bound), and balls (a midpoint and a radius). The property: the interval contains the exact value of A2 at each point of the corpus. |
| A5 | Exact geometric predicates | in progress | Orientation, in-circle and segment intersection. A float filter with a stated error bound answers first, and the exact evaluator answers the rest. A bench against `robust-predicates` on random and near-degenerate inputs. The first users are packing and highways. The package `@mark1russell7/predicates` has `orient2d`, `incircle` and `classifySegments`, each with the stage that decided it. The exact stage uses the dyadic numbers, which moved from the census to this package. On 100 000 random points, the filter decides each call of each predicate (#41). `packages/predicates-bench` and `bench-predicates.yml` time it against `robust-predicates` (#44). Left: the CI run of the bench, which waits for a heavy slot. The package is public and waits for its first publish. |
| A6 | The cost and error model | done 2026-11-03 | Each evaluator measures its cost and its error on the corpus. A selector takes a question and a tolerance, and selects the cheapest evaluator that meets the tolerance. It also stitches them: float first, exact only where the filter fails. The selector is itself measured against each fixed choice. The verb `exact` of `@mark1russell7/expression` gives the exact rational. The package `@algebra/evaluator-select` has the questions, the stitched evaluator and the selector. The package `@algebra/evaluator-bench` and the workflow `bench-select.yml` measure the cost and the error of each stage and of the stitched plan in CI. Run 41716746074 is kept in `packages/evaluator-bench/results/2026-11-03/`. The stitched plan is faster than fixed `exact` over all the cases (median ratio 0.277), slower in the family `ill` (1.185), and gives 0 wrong answers. |
| A7 | Arbitrary precision | in progress | Floats with a precision that the caller selects, and correct rounding of the basic operations. The private package `@algebra/bigfloat` has the number type, the correct rounding of `add`, `sub`, `mul`, `div`, `sqrt` and `root` in four modes, and the verb `bigfloat` of `@mark1russell7/expression` gives an outward interval at a precision of each call. A variable of the verb can have more bits than a double. The stage `bigfloat` of `@algebra/evaluator-select` doubles the precision up to a stated limit, and it gives no answer past that limit. The workflow `bench-bigfloat.yml` of `@algebra/bigfloat-bench` measures each precision and the stage against the verbs `exact` and `interval` on the corpus of A12. Left: the first run of that workflow, the stage in a default plan after that measure, and a page of A11. A literal with more bits needs a change of the documents, so it stays out. |
| A8 | The symbolic evaluator | in progress | A normal form for polynomials and rational functions, simplification, differentiation and the solution of linear and polynomial equations. The package `@algebra/polynomial` adds the verb `polynomial`: one canonical normal form of a polynomial with exact rational coefficients, simplification by that form, and the partial derivative. A result is an exact equality of polynomial functions, with the error 0. A node that the form cannot hold, or a node past a limit, gives no claim. Left: rational functions, the solution of equations, and a bench. |
| A9 | Structures and constructions | later | Monoid, group, ring, field, order and lattice as instances with law tests. Products, quotients, polynomial rings and field extensions. These instances are the first input of the type graph. |
| A10 | vex uses the float evaluator | later | The compiler of vex compiles its formulas through A3, and its domains use the structures of A9. |
| A11 | The site | in progress (#29, #31, #34, #52, A5 explorer) | A live page for each evaluator: type an expression, see each result, its error bound and its cost. The Status page reads this file. The page shows the A1 interval, the A3 float bound, the A4 interval and ball with their widths, the sign that each evaluator proves, and the exact value. It also has an explorer of the float orientation and in-circle signs. A fourth grid shows the stage of the A5 predicate that decided each cell. A section shows the measured cost of each stage, and `select` gives the plan live in the page. Left: the class bars of the census of A13. |
| A12 | The corpus and the CI bench | in progress (#48, #49) | A generator of expressions: well-conditioned and ill-conditioned, small and large, with near-degenerate geometric inputs. CI runs the bench. Each result keeps its raw records, the losers too. The package `@algebra/expression-corpus` has 8 families with seeded points and the exact condition number of each polynomial point (#48). Its first use is the A3 time claim: `packages/expression-bench` and `bench-expression.yml` (#49). Left: the CI run of the bench. It waits for a heavy slot. |
| A13 | The base of A5 | in progress | The real inputs of packing and highways go through the orientation sign of the A1 bounds. The measure is the count of pairs whose sign the float bound cannot fix, each one confirmed by the exact value. A count of 0 ranks A5 lower. The package `@mark1russell7/predicate-census` is the census. It waits for the corpora of highways and packing. |
